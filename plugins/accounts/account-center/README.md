# Cyrene Account Center / Cyrene 账号中心

Account Center owns external account links and short-lived provider credential leases for a verified human anchor `(issuer, subject, organization_id)`. It does not establish Cyrene identity. The current host manifest enables this stateful capability on Linux only, where the private-state runtime validates owner-only permissions; other clients can use the Linux Exchange backend. GitHub OAuth uses the official GitHub App endpoints, `offline_access`, S256 PKCE, and a stable numeric user ID. Its fixed GET callback receives only `code` and `state`; the state digest selects a private session whose verifier is encrypted at rest. WeCom links require a challenge observed by an authenticated connector source and confirmation by the primary user. WeCom identity keys store `source_authority` and `bot_namespace` as separate columns, so slash-containing values cannot collide.

账号中心拥有按可信用户锚点 `(issuer, subject, organization_id)` 作用域隔离的外部账号绑定和短时供应商凭据租约，但不负责建立 Cyrene 身份。当前宿主清单仅在 Linux 上启用此有状态能力，因为该环境提供经过验证的所有者专用私有存储权限；其他客户端可以通过 Linux Exchange 后端使用。GitHub OAuth 使用官方 GitHub App 端点、`offline_access`、S256 PKCE 和稳定数字用户 ID。固定 GET 回调只接收 `code` 和 `state`；state 摘要用于定位私有会话，其中 verifier 经加密后保存。WeCom 绑定必须先由已认证连接器观察挑战，再由主用户确认。WeCom 身份键分别保存 `source_authority` 和 `bot_namespace`，因此包含斜杠的值不会互相碰撞。

| Path | Responsibility |
| --- | --- |
| `plugin.manifest.json` | DirectPluginRuntime entrypoint, methods, state, and secret requirements |
| `contracts/v1/schema.json` | Closed JSON request and response contracts for `account.center.v1` |
| `src/account_center/plugin.py` | Fixed method dispatch, caller policy, link and lease lifecycle |
| `src/account_center/store.py` | Private SQLite migrations, ownership, backup, retention, and one-use lease state |
| `src/account_center/security.py` | Canonical signed caller context and AES-GCM storage envelopes |
| `src/account_center/github.py` | Fixed official GitHub App OAuth, user verification, refresh, and revocation |
| `tests/` | Security and lifecycle regression coverage |

Recommended reading order: contract, security, store, provider client, then plugin dispatch. The no-argument runtime entrypoint reads `CYRENE_CAPABILITY_BINDING_ID`, `CYRENE_CAPABILITY_CONFIGURATION_JSON`, and the host-managed `CYRENE_PLUGIN_STORAGE_PATH`. Account Center stores `accounts.sqlite3` under that existing owner-only `0700` binding directory; activation JSON omits `storage_path` by default. If an explicit path is supplied, it must remain inside the managed directory. Configuration JSON includes `hostSecretRefs`, a map from stable manifest references to environment-variable names; it never includes secret values. `encryption_key_ref`, each `caller_key_refs` value, and `github_client_secret_ref` name entries in that map. The master key and every caller HMAC key must resolve to exactly 32 bytes encoded as hex or base64. Caller roles are fixed in code: Exchange owns user methods and sender resolution, the callback service owns GitHub completion, configured WeCom sources own challenge observation, and the GitHub provider owns lease redemption. `method_callers` can reduce these assignments but cannot expand them. Begin-link, WeCom-confirmation, and unlink use owner/method/key-scoped idempotency records with encrypted replay results and a 24-hour retention window; the signed `request_id` remains a separate one-time replay fence. A legacy WeCom row from schema v1 has no unambiguous namespace column and must be relinked before sender resolution. Missing or inconsistent configuration fails closed. SQLite backups must remain owner-only; unlink clears local credentials immediately and reports remote revocation as pending, failed, or unknown separately. Installation removal follows the manifest's `prompt` retention policy.

建议阅读顺序：先看契约，再看安全实现、存储、供应商客户端，最后看插件分发。无参运行入口读取 `CYRENE_CAPABILITY_BINDING_ID`、`CYRENE_CAPABILITY_CONFIGURATION_JSON` 和宿主管理的 `CYRENE_PLUGIN_STORAGE_PATH`。账号中心在现有且所有者专用的 `0700` 绑定目录中保存 `accounts.sqlite3`；激活 JSON 默认省略 `storage_path`。如显式指定路径，必须位于该托管目录中。配置 JSON 中的 `hostSecretRefs` 将清单稳定引用映射到环境变量名，不能包含密钥值。`encryption_key_ref`、每个 `caller_key_refs` 值和 `github_client_secret_ref` 均引用该映射中的条目。主密钥和每个调用方 HMAC 密钥必须是恰好 32 字节的十六进制或 Base64 编码。调用方角色由代码固定：Exchange 拥有用户方法和发送者解析，回调服务拥有 GitHub 完成方法，已配置的 WeCom 来源拥有挑战观察方法，GitHub 提供方拥有租约兑换方法。`method_callers` 可以收窄这些权限，但不能扩展。开始绑定、确认 WeCom 和解除绑定使用按所有者/方法/密钥隔离的幂等记录，并将重放结果加密保存 24 小时；签名 `request_id` 仍是独立的一次性重放防线。v1 数据库中的旧 WeCom 行缺少无歧义的命名空间列，重新解析发送者前必须重新绑定。缺少或不一致的配置必须拒绝运行。SQLite 备份仅允许所有者访问；解除绑定会立即清除本地凭据，并将远程撤销的待处理、失败或未知状态单独返回。卸载时遵循清单中的 `prompt` 保留策略。
