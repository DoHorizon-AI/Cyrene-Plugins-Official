# Cyrene Account Center / Cyrene 账号中心

Account Center owns provider profiles and short-lived credential leases for a verified human anchor `(issuer, subject, organization_id, workspace_id)`. It does not establish Cyrene identity. The current host manifest enables this stateful capability on Linux only, where the private-state runtime validates owner-only permissions; other clients can use the Linux Exchange backend. GitHub App installation profiles verify the installation with a short-lived RS256 App JWT and mint repository-scoped installation tokens; encrypted token material is reused until near expiry. Fine-grained Hugging Face tokens are resolved only from host secret references, verified with `/api/whoami-v2`, encrypted at rest, and rotated only when the external subject remains the same. Account Center also stores non-secret Azure, GCP, and RunPod host identity references and scope metadata; cloud SDK tokens remain with their provider. Generic one-use leases bind the profile, operation, target, actor, workspace, provider caller, and canonical argument digest. Legacy GitHub OAuth/PKCE and WeCom links remain available when configured.

账号中心按可信用户锚点 `(issuer, subject, organization_id, workspace_id)` 管理 provider profile 和短时凭据租约，但不负责建立 Cyrene 身份。当前宿主清单仅在 Linux 上启用此有状态能力，因为该环境会验证所有者专用私有存储权限；其他客户端可以使用 Linux Exchange 后端。GitHub App 安装 profile 使用短期 RS256 App JWT 验证 installation，并签发限定仓库的 installation token；加密 token 会缓存到接近过期时再续期。细粒度 Hugging Face token 仅通过宿主密钥引用读取，调用 `/api/whoami-v2` 验证后加密保存，且只允许在外部 subject 保持不变时轮换。账号中心还保存 Azure、GCP 和 RunPod 的非敏感宿主 identity reference 与 scope metadata；云 SDK token 留在各自 provider 内。通用一次性租约会绑定 profile、操作、目标、actor、workspace、provider caller 和规范化参数摘要。旧版 GitHub OAuth/PKCE 与 WeCom 绑定仍可在配置后使用。

Recommended reading order: contract, security, store, provider clients, then plugin dispatch. The no-argument runtime entrypoint reads `CYRENE_CAPABILITY_BINDING_ID`, `CYRENE_CAPABILITY_CONFIGURATION_JSON`, and the host-managed `CYRENE_PLUGIN_STORAGE_PATH`. Account Center stores `accounts.sqlite3` under that existing owner-only `0700` binding directory; activation JSON omits `storage_path` by default. If an explicit path is supplied, it must remain inside the managed directory. Configuration JSON includes `hostSecretRefs`, a map from stable manifest references to environment-variable names; it never includes secret values. `encryption_key_ref`, each `caller_key_refs` value, and `github_app_private_key_ref` name entries in that map. GitHub App mode requires `github_app_id` and `github_app_private_key_ref` together and does not use the legacy OAuth client secret or callback. Legacy OAuth fields (`github_callback_uri`, `github_client_id`, `github_client_secret_ref`, `github_callback_caller_id`) are optional as a complete set; when enabled, their caller key and secret refs are required by runtime validation. WeCom caller refs are required only when a WeCom source is configured. The manifest lists these mode-specific refs as optional because they are not needed by every activation. `provider_secret_refs` allowlists HF secret references resolved from the same host map. The master key and every caller HMAC key must resolve to exactly 32 bytes encoded as hex or base64. Exchange owns linking, profile metadata, owner checks, and lease creation; each configured provider caller owns only its matching lease redemption. Callback and WeCom source roles remain fixed when those legacy paths are configured. `method_callers` can reduce assignments but cannot expand them. Link, rotate, and unlink commands use owner/method/key-scoped encrypted idempotency records with a 24-hour retention window; the signed `request_id` remains a separate one-time replay fence. A legacy WeCom row from schema v1 has no unambiguous namespace column and must be relinked before sender resolution. Missing or inconsistent configuration fails closed. SQLite backups must remain owner-only; unlink clears local credentials and invalidates leases. GitHub installation tokens expire remotely and are dropped locally on unlink.

建议阅读顺序：先看契约，再看安全实现、存储、供应商客户端，最后看插件分发。无参运行入口读取 `CYRENE_CAPABILITY_BINDING_ID`、`CYRENE_CAPABILITY_CONFIGURATION_JSON` 和宿主管理的 `CYRENE_PLUGIN_STORAGE_PATH`。账号中心在现有且所有者专用的 `0700` 绑定目录中保存 `accounts.sqlite3`；激活 JSON 默认省略 `storage_path`。如显式指定路径，必须位于该托管目录中。配置 JSON 中的 `hostSecretRefs` 将清单稳定引用映射到环境变量名，不能包含密钥值。`encryption_key_ref`、每个 `caller_key_refs` 值和 `github_app_private_key_ref` 均引用该映射。GitHub App 模式要求 `github_app_id` 与 `github_app_private_key_ref` 成对配置，不使用旧 OAuth client secret 或回调。旧 OAuth 字段（`github_callback_uri`、`github_client_id`、`github_client_secret_ref`、`github_callback_caller_id`）可以整组省略；启用时，运行时会要求对应的 caller key 和 secret 引用。只有配置 WeCom 来源时才需要 WeCom caller 引用。清单将这些按模式启用的引用标为 optional，因为并非每种激活都需要它们。`provider_secret_refs` 将允许使用的 HF 密钥引用限制在同一 host map 中。主密钥和每个调用方 HMAC 密钥必须是恰好 32 字节的十六进制或 Base64 编码。Exchange 负责绑定、profile metadata、所有者检查和租约创建；每个配置的 provider caller 只能兑换对应 provider 的租约。配置旧回调和 WeCom 路径时，回调与 WeCom 来源角色仍固定。`method_callers` 可以收窄权限但不能扩展。绑定、轮换和解除绑定使用按所有者/方法/密钥隔离的幂等记录，并将重放结果加密保存 24 小时；签名 `request_id` 仍是独立的一次性重放防线。v1 数据库中的旧 WeCom 行缺少无歧义的命名空间列，重新解析发送者前必须重新绑定。缺少或不一致的配置必须拒绝运行。SQLite 备份仅允许所有者访问；解除绑定会清除本地凭据并使租约失效。GitHub installation token 会在远端过期，解除绑定后本地副本会清除。
