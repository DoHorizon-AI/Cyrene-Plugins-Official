# Cyrene Account Center / Cyrene 账号中心

Account Center owns provider profiles and short-lived credential leases for a verified human anchor `(issuer, subject, organization_id, workspace_id)`. It does not establish Cyrene identity. The current host manifest enables this stateful capability on Linux only, where the private-state runtime validates owner-only permissions; other clients can use the Linux Exchange backend. GitHub App installation profiles verify the installation with a short-lived RS256 App JWT and mint repository-scoped installation tokens; encrypted token material is reused until near expiry. Typed GitHub App profile leases include the bounded issue, branch, file, Actions, and draft-PR operations. Their targets contain only the stable repository ID/name and exact resource locator; every non-locator argument remains bound by the canonical argument digest. Fine-grained Hugging Face tokens are resolved only from host secret references, verified with `/api/whoami-v2`, encrypted at rest, and rotated only when the external subject remains the same. Account Center also stores non-secret Azure, GCP, and RunPod host identity references and scope metadata; cloud SDK tokens remain with their provider. Generic one-use leases bind the profile, operation, target, actor, workspace, provider caller, and canonical argument digest. Legacy GitHub OAuth/PKCE and WeCom links remain available when configured.

账号中心按可信用户锚点 `(issuer, subject, organization_id, workspace_id)` 管理 provider profile 和短时凭据租约，但不负责建立 Cyrene 身份。当前宿主清单仅在 Linux 上启用此有状态能力，因为该环境会验证所有者专用私有存储权限；其他客户端可以使用 Linux Exchange 后端。GitHub App 安装 profile 使用短期 RS256 App JWT 验证 installation，并签发限定仓库的 installation token；加密 token 会缓存到接近过期时再续期。GitHub App profile 的 typed lease 现覆盖有界 Issue、branch、file、Actions 和 draft PR 操作。target 仅包含稳定仓库 ID/name 与精确资源定位字段；其余参数由规范化参数摘要绑定。细粒度 Hugging Face token 仅通过宿主密钥引用读取，调用 `/api/whoami-v2` 验证后加密保存，且只允许在外部 subject 保持不变时轮换。账号中心还保存 Azure、GCP 和 RunPod 的非敏感宿主 identity reference 与 scope metadata；云 SDK token 留在各自 provider 内。通用一次性租约会绑定 profile、操作、目标、actor、workspace、provider caller 和规范化参数摘要。旧版 GitHub OAuth/PKCE 与 WeCom 绑定仍可在配置后使用。

Recommended reading order: contract, security, store, provider clients, then plugin dispatch. The no-argument runtime entrypoint reads `CYRENE_CAPABILITY_BINDING_ID`, `CYRENE_CAPABILITY_CONFIGURATION_JSON`, and the host-managed `CYRENE_PLUGIN_STORAGE_PATH`. Account Center stores `accounts.sqlite3` under that existing owner-only `0700` binding directory; activation JSON omits `storage_path` by default. If an explicit path is supplied, it must remain inside the managed directory. Configuration JSON includes `hostSecretRefs`, a map from stable manifest references to environment-variable names; it never includes secret values. `encryption_key_ref`, each `caller_key_refs` value, and `github_app_private_key_ref` name entries in that map. GitHub App mode requires `github_app_id` and `github_app_private_key_ref` together and does not use the legacy OAuth client secret or callback. Legacy OAuth fields (`github_callback_uri`, `github_client_id`, `github_client_secret_ref`, `github_callback_caller_id`) are optional as a complete set; when enabled, their caller key and secret refs are required by runtime validation. WeCom caller refs are required only when a WeCom source is configured. The manifest lists these mode-specific refs as optional because they are not needed by every activation. `provider_secret_refs` allowlists HF secret references resolved from the same host map. The master key and every caller HMAC key must resolve to exactly 32 bytes encoded as hex or base64. Exchange owns linking, profile metadata, owner checks, and lease creation; each configured provider caller owns only its matching lease redemption. Callback and WeCom source roles remain fixed when those legacy paths are configured. `method_callers` can reduce assignments but cannot expand them. Link, rotate, and unlink commands use owner/method/key-scoped encrypted idempotency records with a 24-hour retention window; the signed `request_id` remains a separate one-time replay fence. A legacy WeCom row from schema v1 has no unambiguous namespace column and must be relinked before sender resolution. Missing or inconsistent configuration fails closed. SQLite backups must remain owner-only; unlink clears local credentials and invalidates leases. GitHub installation tokens expire remotely and are dropped locally on unlink.

建议阅读顺序：先看契约，再看安全实现、存储、供应商客户端，最后看插件分发。无参运行入口读取 `CYRENE_CAPABILITY_BINDING_ID`、`CYRENE_CAPABILITY_CONFIGURATION_JSON` 和宿主管理的 `CYRENE_PLUGIN_STORAGE_PATH`。账号中心在现有且所有者专用的 `0700` 绑定目录中保存 `accounts.sqlite3`；激活 JSON 默认省略 `storage_path`。如显式指定路径，必须位于该托管目录中。配置 JSON 中的 `hostSecretRefs` 将清单稳定引用映射到环境变量名，不能包含密钥值。`encryption_key_ref`、每个 `caller_key_refs` 值和 `github_app_private_key_ref` 均引用该映射。GitHub App 模式要求 `github_app_id` 与 `github_app_private_key_ref` 成对配置，不使用旧 OAuth client secret 或回调。旧 OAuth 字段（`github_callback_uri`、`github_client_id`、`github_client_secret_ref`、`github_callback_caller_id`）可以整组省略；启用时，运行时会要求对应的 caller key 和 secret 引用。只有配置 WeCom 来源时才需要 WeCom caller 引用。清单将这些按模式启用的引用标为 optional，因为并非每种激活都需要它们。`provider_secret_refs` 将允许使用的 HF 密钥引用限制在同一 host map 中。主密钥和每个调用方 HMAC 密钥必须是恰好 32 字节的十六进制或 Base64 编码。Exchange 负责绑定、profile metadata、所有者检查和租约创建；每个配置的 provider caller 只能兑换对应 provider 的租约。配置旧回调和 WeCom 路径时，回调与 WeCom 来源角色仍固定。`method_callers` 可以收窄权限但不能扩展。绑定、轮换和解除绑定使用按所有者/方法/密钥隔离的幂等记录，并将重放结果加密保存 24 小时；签名 `request_id` 仍是独立的一次性重放防线。v1 数据库中的旧 WeCom 行缺少无歧义的命名空间列，重新解析发送者前必须重新绑定。缺少或不一致的配置必须拒绝运行。SQLite 备份仅允许所有者访问；解除绑定会清除本地凭据并使租约失效。GitHub installation token 会在远端过期，解除绑定后本地副本会清除。

Hugging Face `device_oauth` bootstrap reads the final, closed credential DTO only from the launcher-mounted `hostSecretFileRefs` path named by `provider_secret_file_refs`; the DTO never enters an Account Center request or environment variable. Account Center verifies the initial subject with the fixed Hub identity endpoint, stores encrypted access and refresh tokens in its persistent database, and commits any rotated refresh token before returning an access token. A revoked or uncertain refresh clears usable OAuth material and reports reauthorization required. Owner-initiated reauthorization uses Hugging Face's official device-code flow with the profile's exact stored OAuth scopes; its device code is encrypted in a durable private session and never leaves Account Center. Completion must preserve the existing Hub subject, repository allowlist, and scope set. `oauth_scopes: null` means the Hub did not return a scope claim; it is never expanded into assumed permissions. The explicit repository allowlist remains mandatory. `workspace_operator_profile_refs` is a launcher-owned opt-in list, and shared-mode leases require a fresh, one-use grant proof signed by Exchange.

Hugging Face `device_oauth` bootstrap 只从启动器挂载的 `hostSecretFileRefs` 路径读取最终闭合凭据 DTO，该路径由 `provider_secret_file_refs` 指定；DTO 不会进入账号中心请求或环境变量。账号中心会通过固定 Hub 身份端点核验初始 subject，将加密的 access/refresh token 持久化到数据库，并在返回 access token 前提交轮换后的 refresh token。撤销或结果不确定的刷新会清除可用 OAuth 凭据并报告需要重新授权。所有者发起的重新授权使用 Hugging Face 官方设备码流程，并沿用 profile 中精确保存的 OAuth scope；device code 以密文存储在持久私有会话中，不会离开账号中心。完成后必须保留原 Hub subject、仓库 allowlist 与 scope 集合。`oauth_scopes: null` 表示 Hub 未返回 scope 声明，绝不推断或扩张权限。显式仓库 allowlist 始终生效。`workspace_operator_profile_refs` 是启动器专用的显式共享名单；共享模式的租约必须带有 Exchange 签名且短时、一次性的授权证明。
