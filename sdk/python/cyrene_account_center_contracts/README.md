# Account Center Python contracts

`cyrene_account_center_contracts` contains DTOs and canonical HMAC signing helpers for the owner-scoped `account.center.v1` contract. It does not perform OAuth, persistence, or provider operations. `BeginLinkRequest`, `ConfirmWeComLinkRequest`, and `UnlinkRequest` carry the Exchange `Idempotency-Key` as `idempotency_key`; Account Center returns the encrypted original result for an identical body/key/owner tuple and rejects changed-body reuse. `CompleteGitHubLinkRequest` contains only `state` and `code`, matching GitHub's fixed GET callback; Account Center resolves the owner from its state-digest session and encrypted S256 PKCE verifier. `ResolveLinkedSenderRequest` carries the exact source authority, bot namespace, and stable subject tuple; its response contains the stored primary anchor only when linked. Caller keys must be injected privately, with independent keys for each configured service caller; master and caller HMAC keys are exactly 32 bytes.

`cyrene_account_center_contracts` 提供 owner-scoped `account.center.v1` 的 DTO 和规范化 HMAC 签名工具，不执行 OAuth、持久化或供应商操作。`BeginLinkRequest`、`ConfirmWeComLinkRequest` 和 `UnlinkRequest` 通过 `idempotency_key` 携带 Exchange 的 `Idempotency-Key`；账号中心对相同正文、密钥和所有者元组返回加密保存的原始结果，并拒绝相同密钥搭配不同正文。`CompleteGitHubLinkRequest` 只包含 `state` 和 `code`，与 GitHub 固定 GET 回调一致；账号中心通过 state 摘要会话和加密的 S256 PKCE verifier 确定所有者。`ResolveLinkedSenderRequest` 携带精确的来源 authority、bot namespace 和稳定 subject 元组；仅绑定成功时响应才包含已保存的主锚点。调用方密钥必须通过私密方式注入，并为每个已配置服务调用方单独配置；主密钥和调用方 HMAC 密钥均恰好为 32 字节。
