# Account Center Python contracts

`cyrene_account_center_contracts` contains DTOs and canonical HMAC signing helpers for the owner-scoped `account.center.v1` contract. Canonical JSON and SHA-256 payload digests use RFC 8785 (JCS), so Python and JavaScript/TypeScript callers produce the same bytes; non-finite numbers and integers outside the safe JSON number range are rejected. It does not perform OAuth, persistence, or provider operations. `BeginLinkRequest`, `ConfirmWeComLinkRequest`, and `UnlinkRequest` carry the Exchange `Idempotency-Key` as `idempotency_key`; Account Center returns the encrypted original result for an identical body/key/owner tuple and rejects changed-body reuse. `LinkGitHubAppInstallationRequest` and `LinkHuggingFaceProfileRequest` carry only profile metadata and stable host secret references, never secret values. `CreateProviderCredentialLeaseRequest` and `RedeemProviderCredentialLeaseRequest` bind `profile_ref`, exact operation, provider target, and canonical argument digest; only the provider caller receives `AuthMaterial` after one-use redemption. `ProviderProfile` and `ListProviderProfilesResponse` expose metadata and auth health without credentials. `RegisterHostIdentityProfileRequest` records non-secret Azure, GCP, and RunPod host identity references. Caller keys must be injected privately, with independent keys for each configured service caller; master and caller HMAC keys are exactly 32 bytes.

`BeginMicrosoftGraphLinkRequest` preserves the v1 Planner-plan selector and adds a mutually exclusive `office_v2_scope` selector for Office v2. Exchange omits the unset selector when producing the exact Account Center payload, so v1 still sends only `planner_plan_ids` and v2 sends only `office_v2_scope`; neither form accepts caller-selected OAuth scopes. `UpdateMicrosoftGraphV2ScopeRequest` binds a resource-selection CAS update to the profile, workspace, expected credential revision, target scope, and idempotency key. It cannot change feature grants or OAuth permissions. `BeginMicrosoftGraphScopeUpgradeRequest` remains a closed permission upgrade. `BeginAzureDevOpsLinkRequest` carries one source tuple from trusted Exchange host settings and the expected Entra tenant UUID. The corresponding completion DTOs carry only PKCE `state` and authorization `code`. All flows return session metadata without credentials. Graph and Azure DevOps provider leases use the same generic lease DTOs and include an optional `profile_scope_sha256` so the provider can verify the profile scope used for the operation.

`cyrene_account_center_contracts` 提供 owner-scoped `account.center.v1` 的 DTO 和规范化 HMAC 签名工具。规范 JSON 和 SHA-256 参数摘要使用 RFC 8785（JCS），确保 Python 与 JavaScript/TypeScript 调用方生成相同字节；拒绝非有限数值和超出安全 JSON 数值范围的整数。该包不执行 OAuth、持久化或供应商操作。`BeginLinkRequest`、`ConfirmWeComLinkRequest` 和 `UnlinkRequest` 通过 `idempotency_key` 携带 Exchange 的 `Idempotency-Key`；账号中心对相同正文、密钥和所有者元组返回加密保存的原始结果，并拒绝相同密钥搭配不同正文。`LinkGitHubAppInstallationRequest` 与 `LinkHuggingFaceProfileRequest` 只携带 profile metadata 和稳定的宿主密钥引用，不携带密钥值。`CreateProviderCredentialLeaseRequest` 与 `RedeemProviderCredentialLeaseRequest` 绑定 `profile_ref`、精确操作、供应商目标和规范化参数摘要；只有 provider caller 能在一次性兑换后取得 `AuthMaterial`。`ProviderProfile` 和 `ListProviderProfilesResponse` 只公开 metadata 与授权健康状态。`RegisterHostIdentityProfileRequest` 记录非敏感的 Azure、GCP 和 RunPod 宿主身份引用。调用方密钥必须通过私密方式注入，并为每个已配置服务调用方单独配置；主密钥和调用方 HMAC 密钥均恰好为 32 字节。

`BeginMicrosoftGraphLinkRequest` 保留 v1 Planner plan 选择字段，并增加与其互斥的 Office v2 `office_v2_scope` 字段。Exchange 生成精确 Account Center payload 时会移除未设置的字段，因此 v1 仍只发送 `planner_plan_ids`，v2 只发送 `office_v2_scope`；两种形式都不接受调用方自选 OAuth scope。`UpdateMicrosoftGraphV2ScopeRequest` 将资源选择 CAS 更新绑定到 profile、workspace、预期凭据 revision、目标 scope 和幂等键，且不能改变功能授权或 OAuth 权限。`BeginMicrosoftGraphScopeUpgradeRequest` 仍只选择一种闭合的权限升级。`BeginAzureDevOpsLinkRequest` 携带来自可信 Exchange 宿主配置的一个 source tuple 与预期 Entra tenant UUID。对应的完成 DTO 仅携带 PKCE `state` 和授权 `code`。所有流程都只返回不含凭据的 session metadata。Graph 与 Azure DevOps provider lease 复用同一通用 DTO，并可带上 `profile_scope_sha256`，让 provider 验证本次操作对应的 profile scope。
