# Connector Operations / 连接器操作清单

`v1/connector-operations.json` lists every operation Platform can grant to a connector, with what Exchange and Navigator record about it. It is generated by running those three repositories' real code at the exact commits in `sources`.

**Nothing reads this file yet.** It changes no behavior. Later work is meant to load it in place of the constants it was generated from, and will add the facts it needs, such as Exchange's per-provider validators.

| Field | Comes from |
| --- | --- |
| `operationId`, `providerIds`, `automationTransport` | Platform's grant functions, called for every provider and operation |
| `roles` | Platform's `require_directory_connector_operation_role`, called for each role. Holding `automationViewer` does not make an operation read-only: see `automationTransport` |
| `exchangeToolIds`, `exchangeResourceProjections` | Exchange's `_TOOL_IDS_BY_PROVIDER` and `connector_binding_tools`, imported |
| `mutating` | Exchange's `_MUTATING_OPERATIONS` and Navigator's table, which must agree |
| `navigatorToolId`, `navigatorResourceProjection` | Navigator's `connectorOperationPolicy`, run. `null` when the operation is not in its table |
| `scopeLockBranchField` | Navigator's `connectorScopeLock`, run |
| `profileIsOuterClaim` | Navigator's expression, run. `null` for a provider Navigator does not bind |

`exchangeOnlyOperations` lists operations Exchange maps but Platform cannot grant, so a connector grant cannot reach them. They are recorded, not endorsed.

## Disagreements the tool accepts

The tool refuses any disagreement between sources, except these, which are listed by name in `manifest.py`. It also refuses if one of them stops being true.

| Operation | Disagreement |
| --- | --- |
| `msteams.message.reply` | Exchange's prepare path says it does not mutate, and its ledger path says it does, so `mutating` is `null` |
| `microsoft_graph.calendar.events.list` | Exchange's launcher map says `microsoft_graph_event`, Navigator says `microsoft_graph_calendar` |
| `microsoft_graph.todo.tasks.list` | Exchange's launcher map says `microsoft_graph_todo_task`, Navigator says `microsoft_graph_todo_list` |

## Regenerating

From clean checkouts, with Rust, Node 22.6 or later, and a Python environment that has Exchange's dependencies. The Exchange code itself is imported from the checkout, and the command refuses anything else.

```bash
python3 tooling/connector_operations/manifest.py probe --platform PATH --exchange PATH --exchange-python PATH --navigator PATH --dumps DIR
python3 tooling/connector_operations/manifest.py generate --dumps DIR
```

The `connector-operations` CI job runs `probe` and `check` at the pinned commits, and requires them to be merged. It proves the file matches those commits, not the current heads of the other repositories.

# 连接器操作清单

`v1/connector-operations.json` 列出 Platform 能授权给连接器的每个操作，以及 Exchange 和 Navigator 对它的记录。它通过运行这三个仓库在 `sources` 所记录精确提交上的真实代码生成。

**目前还没有代码读取这个文件**，它不改变任何行为。后续工作会用它代替生成它的那些常量，并补充所需的信息，例如 Exchange 按 provider 的校验。

| 字段 | 来源 |
| --- | --- |
| `operationId`、`providerIds`、`automationTransport` | Platform 的授权函数，对每个 provider 和操作调用 |
| `roles` | Platform 的 `require_directory_connector_operation_role`，对每个角色调用。拥有 `automationViewer` 不代表操作是只读的，见 `automationTransport` |
| `exchangeToolIds`、`exchangeResourceProjections` | 导入 Exchange 的 `_TOOL_IDS_BY_PROVIDER` 和 `connector_binding_tools` |
| `mutating` | Exchange 的 `_MUTATING_OPERATIONS` 和 Navigator 的操作表，两者必须一致 |
| `navigatorToolId`、`navigatorResourceProjection` | 运行 Navigator 的 `connectorOperationPolicy`；操作不在表中时为 `null` |
| `scopeLockBranchField` | 运行 Navigator 的 `connectorScopeLock` |
| `profileIsOuterClaim` | 运行 Navigator 的表达式；Navigator 不绑定的 provider 为 `null` |

`exchangeOnlyOperations` 列出 Exchange 有映射、但 Platform 不能授权的操作，连接器授权到不了它们。这里只是记录，不代表认可。

## 工具接受的分歧

来源之间有分歧时工具会拒绝，只有下面这些例外，它们按名称写在 `manifest.py` 里。其中任何一条不再成立时，工具也会拒绝。

| 操作 | 分歧 |
| --- | --- |
| `msteams.message.reply` | Exchange 的准备路径说它不修改数据，账本路径说它修改，所以 `mutating` 为 `null` |
| `microsoft_graph.calendar.events.list` | Exchange 的启动映射是 `microsoft_graph_event`，Navigator 是 `microsoft_graph_calendar` |
| `microsoft_graph.todo.tasks.list` | Exchange 的启动映射是 `microsoft_graph_todo_task`，Navigator 是 `microsoft_graph_todo_list` |

## 重新生成

需要干净的检出、Rust、Node 22.6 或更新版本，以及装有 Exchange 依赖的 Python 环境。Exchange 代码本身从检出导入，其他来源会被拒绝。

```bash
python3 tooling/connector_operations/manifest.py probe --platform PATH --exchange PATH --exchange-python PATH --navigator PATH --dumps DIR
python3 tooling/connector_operations/manifest.py generate --dumps DIR
```

CI 任务 `connector-operations` 在固定提交上运行 `probe` 和 `check`，并要求这些提交已经合并。它证明的是文件和这些提交一致，不是和其他仓库的最新代码一致。
